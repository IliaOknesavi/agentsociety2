# polity

Наш код поверх AgentSociety 2: сравнение форм власти на одной популяции агентов. Файлы каркаса лежат в остальных папках репозитория и здесь не меняются.

## Город на рельсах

Приложение, в котором город запускается и просматривается по месяцам: [city/README.md](city/README.md).
Среда `CityRailsEnv` и агент `ResidentAgent` лежат в разделе готовых модулей каркаса
(`packages/agentsociety2/agentsociety2/contrib/env/city_rails/` и `contrib/agent/resident_agent.py`): так каркас
находит их сам по имени класса. Это новые файлы, существующие файлы каркаса не изменены.

## Модель по подписке: Claude или ChatGPT

AgentSociety 2 обращается к модели по HTTP. `llm/subscription_shim.py` это локальный сервер, который принимает такой запрос и выполняет его по подписке, без ключа API. Путей три:

- **Claude**: `claude -p` (Claude Code).
- **ChatGPT напрямую**: провайдер `chatgpt/` библиотеки LiteLLM, которая уже стоит в окружении каркаса. Запрос уходит на сервер подписки без CLI, вызов функций настоящий.
- **Codex CLI**: `codex app-server` (встраиваемый режим Codex: один постоянный процесс, запросы по JSON-RPC). Запасной путь для подписки ChatGPT: медленнее и добавляет к запросу много своего текста.

```bash
# из корня репозитория, после uv sync --package agentsociety2
polity/run_with_subscription.sh packages/agentsociety2/examples/games/02_public_goods.py
MODEL=sonnet polity/run_with_subscription.sh packages/agentsociety2/examples/games/02_public_goods.py
MODEL=chatgpt/gpt-6.2-sol polity/run_with_subscription.sh packages/agentsociety2/examples/games/02_public_goods.py
MODEL=codex polity/run_with_subscription.sh packages/agentsociety2/examples/games/02_public_goods.py
```

Скрипт поднимает прокладку, задаёт каркасу адрес и имя модели, запускает сценарий в `polity/runs/` и в конце печатает счётчики.

| `MODEL` | Куда идёт запрос |
|---|---|
| `haiku`, `sonnet`, `opus` | Claude через `claude -p` |
| `chatgpt/<имя модели>` | подписка ChatGPT напрямую, имя модели обязательно |
| `codex` | Codex CLI через `codex app-server`, модель по умолчанию |
| `codex/<имя модели>` | Codex CLI с указанной моделью |

Каркасу скрипт передаёт только путь (`chatgpt`, `codex`), имя модели получает одна прокладка. Клиент LiteLLM внутри каркаса сверяет параметры запроса с именем модели и для имён GPT, которых нет в его встроенной карте (например `gpt-6.2-sol`), отказывается слать `tool_choice`: шаг агента с инструментами падает с `UnsupportedParamsError`. Поэтому при ручном запуске без скрипта задавайте `AGENTSOCIETY_LLM_MODEL=chatgpt` и `SHIM_MODEL_NAME=<имя модели>`.

Прямой путь к ChatGPT требует одного входа на машине. Сначала в настройках безопасности ChatGPT включите вход по коду устройства, затем выполните команду: она напечатает адрес и код и дождётся подтверждения в браузере.

```bash
.venv/bin/python -c "from litellm.llms.chatgpt.authenticator import Authenticator; Authenticator().get_access_token()"
```

Вход хранится в `~/.config/litellm/chatgpt/auth.json` и обновляется сам. LiteLLM при этом представляется серверу программой Codex: это клиент сообщества, OpenAI его не выпускала и может закрыть такой доступ. Если он перестанет работать, остаётся `MODEL=codex`.

- **Кэш.** Ответы хранятся в `polity/.cache/llm.sqlite` по ключу из модели и полного текста запроса. Повтор прогона с теми же промптами не вызывает модель и даёт те же ответы.
- **Счётчики.** `GET /stats`: настоящие вызовы, попадания в кэш, токены, цена по тарифу API (Claude её сообщает, ChatGPT и Codex нет; по подписке деньги не списываются). Каждый настоящий вызов пишется строкой в `polity/.cache/calls.jsonl`.
- **Проверка без модели.** `python polity/llm/subscription_shim.py --selftest`.

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `MODEL` | `haiku` | модель для сценария |
| `PORT` | `18765` | порт прокладки |
| `SHIM_MAX_CALLS` | без предела | предел настоящих вызовов модели за запуск прокладки |
| `SHIM_CONCURRENCY` | `8` | сколько вызовов модели идёт одновременно |
| `SHIM_EFFORT` | `low` | усилие рассуждения модели |
| `SHIM_PROMPTS` | выключено | путь к файлу, куда писать полный текст запросов |
| `SHIM_MODEL_NAME` | из `MODEL` | имя модели для путей `chatgpt` и `codex`; скрипт запуска берёт его из части `MODEL` после косой черты |
| `SHIM_CODEX_HOME` | не задана | отдельная папка настроек Codex CLI для симуляций, см. ниже |
| `SHIM_CODEX_MODE` | `app-server` | `exec`: запасной путь, отдельный процесс `codex exec` на каждый вопрос |
| `SHIM_CACHE`, `SHIM_LOG` | `polity/.cache/` | где лежат кэш и журнал |

## Что каждый путь добавляет к запросу от себя

`claude -p` и Codex CLI это программы для разработки, и к каждому запросу они дописывают свой служебный текст. Прокладка отключает всё, что отключается, и запускает CLI из пустой папки. На прямом пути к ChatGPT лишнего текста нет: LiteLLM по умолчанию ставит перед промптом инструкцию Codex (около 1 650 токенов), прокладка это отключает.

| | Claude | ChatGPT напрямую | Codex CLI |
|---|---|---|---|
| Системный промпт | заменяется нашим целиком | уходит как есть | заменяется нашим (`baseInstructions` треда) |
| Остаток сверху | около 990 токенов: почта аккаунта, дата, имя модели | нет | около 9 500 токенов: описания встроенных инструментов, личный `~/.codex/AGENTS.md`, блоки о навыках и мультиагентности |
| Время вызова | 8-11 секунд | 2-5 секунд, первый около 10 | 8-26 секунд |
| Вызов функций | ответ по JSON-схеме, протокол описан в промпте | настоящий | ответ по JSON-схеме, протокол описан в промпте |
| Встроенные инструменты программы | отключены полностью | их нет | часть остаётся и флагами не убирается: запуск команд в песочнице только для чтения, запуск субагентов |

Личный `AGENTS.md` у каждого свой, поэтому на Codex CLI с домашними настройками агенты у разных людей получают разный текст. Если нужен именно этот путь, заведите Codex отдельную чистую папку настроек и войдите в ней один раз:

```bash
CODEX_HOME=~/.codex-polity codex login
SHIM_CODEX_HOME=~/.codex-polity MODEL=codex polity/run_with_subscription.sh сценарий.py
```

Общие ограничения:

- вероятностей вариантов, температуры и зерна нет; воспроизводимость даёт кэш;
- эмбеддингов нет: кэш переводов в маршрутизаторе каркаса работает по точному совпадению текста запроса.
